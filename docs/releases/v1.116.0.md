# Release: v1.116.0: Background Export System with S3 Storage

## Major Changes

This release introduces a comprehensive background export system, fundamentally changing how data exports are handled in the CRM. Exports are now processed asynchronously by a dedicated backend pipeline, stored in S3, and support recurring schedules — removing size and time limits that previously constrained exports run directly from the browser.

The export architecture was reworked end-to-end: a new data model for export tasks, a Lambda-based background processor, permissioned cross-account access for shared S3 locations, and a dedicated bucket for recurring exports.

## Fixes

- Meetings view now shows a clear loading indicator and an explicit empty state when there are no meetings to display.
- Notes that reference blocks without associated `people` records no longer break the UI or export pipeline.
- Removed leftover references to exporting a person's data that no longer apply in the new export model.

## Details

### Background Export System

The export feature has moved from an in-browser, synchronous operation to a background-processed pipeline:

- New data model for export tasks captures the lifecycle of each export request (queued → processing → completed/failed).
- A dedicated Lambda function (`process-export-tasks`) picks up queued tasks and performs the heavy lifting server-side.
- Completed exports are uploaded to S3 and made available to the user via signed URLs, bypassing browser memory and timeout limits.
- The backend architecture was restructured to cleanly separate task loading, data fetching, markdown generation, and S3 upload concerns.

### Recurring Exports with Cross-Account S3 Permissions

Users can now schedule recurring exports:

- Recurring exports run on a defined cadence and write to a dedicated S3 bucket.
- Cross-account permissions are configured so exported data can be shared with external AWS accounts without manual credential sharing.
- A schedule handler and permission handler manage the lifecycle of recurring export rules.

### Unified S3 Storage for All Exports

All export output — one-time and recurring — now flows through S3:

- One-time exports and recurring exports share a consistent S3-backed storage model, with the recurring bucket isolated for cross-account sharing.
- Client code fetches export results from S3 rather than producing them in-browser, improving reliability for larger datasets.

### Smaller Changes

- Reworked internal helpers for export tasks: new `activities.ts`, `dynamodb.ts`, `handle-one-time-export.ts`, and `tiptap-doc.ts` modules; removed obsolete per-entity fetching and query files.
- Cleaned up export-related test fixtures and helper tests that no longer apply to the new architecture.
- Updated backend wiring (`backend.ts`, `export-tasks.ts`) and AI schema to support the new export flow.
- Regenerated GraphQL client code to reflect schema changes for export tasks.
